# Relief 要件定義

## 目的

- アトピー肌状態を日次で記録し、食事・水分・症状を可視化する
- AIによる糖質・塩分・タンパク質推定と日次アドバイスでセルフケアを支援する
- アトピービジネスに惑わされず、多額のお金や外用ステロイドを使わずに、自分でコントロールできるようにほしい思い。

## ゴール

- デイリーで肌の状態をセルフケアすることで自身の生活を振り返ることにより、肌のコントロールができるようにする
- 肌のコントロールをすることで自然に肌の回復するための補助的なツールとして使用される

## 対象ユーザー

- アトピー性皮膚炎の人向けで、かゆみや肌トラブルを日々記録し、傾向を把握したいユーザー。

# 参考とするデータ

- 本アプリは以下の療法を取り入れたものとする
  - 脱保湿療法
  - 脱ステロイド療法
  - 糖質制限によるヒスタミン抑止
  - 浸出液を防ぐため、水分制限と運動をセットで行う療法

## 制約事項

- 参考とするデータをもとにアプリは作られているが、セルフケア(ウェルネスアプリ)を目的とするため、医療的な診断は行わないこと。
- 日次アドバイス、相談チャットも医療的な行為は禁止。
- 注意文言として、主治医や皮膚科へ相談する旨を追加すること。

## 機能要件
- 選択中の日付の天気・最高/最低気温・湿度・現在地名を表示
- 日付を選択して当日の記録を入力・編集できること
- 日付はカレンダー機能で指定できること。今日の日付を指定できること
- ダッシュボードでの表示と各種入力機能を分けたUIとする
- かゆみスコア、水分量、メモ(肌の状態等で気づいたこと)、食事内容を記録できること
- 水分制限をするなどといった指示も出さないこと。
- 推定値はユーザーが上書きできること
- プラン構成（2段階）
  - **Freeプラン**: 広告表示のみ。全機能（かゆみ傾向グラフ含む）は標準で利用可能
  - **Fullプラン**: 広告非表示・Google Driveデータバックアップ・主治医向けレポート作成
- ユーザー認証は **Google OAuth 専用** とする（メールアドレス・パスワード認証は使用しない）
- ログイン後の表示はGoogleアカウントの表示名（ニックネーム）とする
- メールアドレスは個人情報のため保存・表示しないこと。
- 表示言語は日本語・英語を切り替えられること（設定画面で変更）

## 非機能要件

- モバイルファーストで見やすいUIであること。
- モバイルアプリ内に記録すること
- 画面操作が軽快で、入力が簡単であること

# Relief 機能仕様書

## 概要
アトピー肌状態を記録し、AIで糖質・塩分・タンパク質推定と日次アドバイスを行うセルフケア支援アプリ

## 主要機能

- 天気情報の表示
  - 選択日の天気・最高/最低気温・湿度・現在地名（市区町村, 都道府県）
  - ブラウザの Geolocation API で現在地を自動取得
  - 天気取得失敗時は「—」で表示（地名は非表示）
- 日次記録の入力
  - 摂取水分、1日の合計水分量、かゆみ状態、かゆみの部位、運動内容、食事、糖質・塩分・タンパク質、メモ
- 過去の入力を確認（カレンダーで指定）
- かゆみ傾向グラフ（全ユーザー利用可）
  - 月次: 当年1〜12月のかゆみスコア平均の折れ線グラフ
  - 週次: 選択した月の全週（4〜5週）のかゆみスコア平均の折れ線グラフ
- Fullプランコンテンツ
  - Google Drive へのデータバックアップ・復元
  - 主治医向けレポート作成（印刷/PDF保存）
  - 広告非表示

## プラン詳細

| 機能 | Free | Full |
| --- | :---: | :---: |
| 日次記録・かゆみ傾向グラフ | ✓ | ✓ |
| 広告表示 | あり | なし |
| Google Drive バックアップ | - | ✓ |
| 主治医向けレポート | - | ✓ |

  - 日付の下に選択日の天気情報（天気・最高/最低気温・湿度・地名）を表示
- ダッシュボード
  以下をボトムナビゲーションバー（画面下部固定）でタブ切り替えする
  - 今日のまとめ
    以下の順でレイアウトをする

    | 項目 | 構成 |
    | - | - |
    | 水分 | 1枠でレイアウト |
    | 月次水分のグラフ | 1枠でレイアウト |
    | 運動 | 1枠でレイアウト |
    | かゆみスコア / 糖質 / 塩分 / タンパク質 | 1枠・4列でレイアウト |
    | かゆみ傾向グラフ | 1枠でレイアウト（全ユーザー表示）|

  - 入力グリッド（水分/運動/食事 + 栄養(手動入力もできるように) + AI推定ボタン / かゆみ / メモ）
- ボトムナビゲーションバー（固定・iOS標準スタイル）
  - 「📊 まとめ」「✏️ 入力」「設定」3タブをタップで切り替え

## 天気情報仕様

- 表示場所: カレンダーカード内・日付行の下（セパレーター区切り）
- 表示項目: 📍 地名（市区町村, 都道府県）/ 天気アイコン・状態名 / 🌡 最高°/最低° / 💧 湿度%
- 天気状態の分類（WMO天気コード対応）

  | WMO コード | アイコン | 状態名 |
  | --- | --- | --- |
  | 0 | ☀️ | 晴れ |
  | 1〜2 | ⛅ | くもり時々晴れ |
  | 3 | ☁️ | くもり |
  | 45〜48 | 🌫️ | 霧 |
  | 51〜57 | 🌧️ | 霧雨 |
  | 61 | 🌂 | 小雨 |
  | 63 | 🌧️ | 雨 |
  | 65〜67 | ☔ | 大雨 |
  | 71〜77 | ❄️ | 雪 |
  | 80〜82 | 🌦️ | にわか雨 |
  | 85〜86 | 🌨️ | にわか雪 |
  | 95〜 | ⛈️ | 雷雨 |

- 取得方法
  - 位置情報: ブラウザの Geolocation API（初回のみ許可ダイアログ表示。以降はキャッシュ）
  - 天気: Open-Meteo API（無料・APIキー不要）
    - 90日以内: Forecast API（`/v1/forecast`）
    - 90日より前: Archive API（`/v1/archive`）
  - 地名: Nominatim / OpenStreetMap（無料・APIキー不要）の逆ジオコーディング
- キャッシュ
  - 今日の天気: 30分
  - 過去日の天気: 24時間（変化しないため）
  - 地名: 24時間
- エラー時の挙動
  - 位置情報の許可拒否: 「位置情報を許可すると天気が表示されます」と表示
  - 天気取得失敗: 各項目を「—」で表示
  - 天気取得失敗時は地名の取得リクエスト自体を行わない
- 環境変数（未設定時はデフォルト値にフォールバック）
  - `OPEN_METEO_FORECAST_URL`: Forecast API エンドポイント
  - `OPEN_METEO_ARCHIVE_URL`: Archive API エンドポイント
  - `NOMINATIM_URL`: Nominatim API エンドポイント

## かゆみ傾向グラフ仕様

- 全ユーザーが利用可能（プラン制限なし）
- 月次/週次をボタンで切り替え
- **月次モード**
  - 当年1〜12月を常に表示（データがない月は0で表示）
  - X軸: 1〜12月の目盛り
  - 季節ごと・季節の変わり目のかゆみ傾向を把握する目的
- **週次モード**
  - 月ナビゲーター（‹ 年月 ›）で表示月を切り替え
  - 選択月の全週（4〜5週）を常に表示（データがない週は0で表示）
  - X軸: 各週の開始日（月曜日）の目盛り
- Y軸: 0〜5（アイコン）の1刻み（かゆみスコアに対応）
- 各期間のかゆみスコア平均値を折れ線グラフで表示（1本）
- 記録なし（スコア未入力・削除済み）の期間は平均計算から除外し、折れ線を切断する

## 入力項目
以下の順にする

- 水分
  - その日の水分合計（ml）
  - こまめに水分を取るために追加する方式とする。入力は時間,摂取水分量とする。これはログとしてDBに保存する
  - 時間は現在時刻とする。また修正できるようにする。
  - 時刻順に自動的にソートすること
  - 水分の指定は「任意入力」「+50ml」 「+100ml」 「+150ml」とする
  - 1日の最大摂取水分を設定ができるようにする。グラフで表すようにする。
  - 糖質・塩分・タンパク質の1日最大摂取量を設定できるようにする。設定画面で行う。
- 運動（何時間）
  - ウォーキング 00km
  - ランニング  00km
- 食事内容（自由記述）
  - 栄養の糖質/塩分/タンパク質の入力（AIで推定した場合は自動入力）
  - AIで糖質/塩分/タンパク質を推定するボタン
- かゆみ
  - かゆみの部位（チップ式マルチセレクト・複数選択可）
    - 頭 / 顔 / 首 / 腕・ひじの内 / 手・ゆび / 胸・お腹 / 背中 / 太もも / ひざの裏 / ふくらはぎ / 足
  - かゆみスコア（アイコンにする）
    - 5:辛いアイコン
    - 4:悪いアイコン
    - 3:まぁまぁ画面できるアイコン
    - 2:かなり楽なアイコン
    - 1:かゆみなしアイコン
- メモ（任意）

## データバックアップ仕様（Fullプランのみ）

- Google Drive の `atolog` フォルダへ gzip 圧縮 JSON 形式でエクスポート
- バックアップ内容: 全日次記録 + ユーザー設定（plan は除外）
- ファイル名: `atolog-backup.json.gz`（固定名。上書き保存）
- 復元時は同フォルダ内の固定名ファイルを自動検索して復元
- OAuth スコープ: `https://www.googleapis.com/auth/drive.file`（自アプリ作成ファイルのみ）

## 主治医向けレポート仕様（Fullプランのみ）

- `/report` ページで表示
- 表示期間: 過去1ヶ月 / 3ヶ月 / 6ヶ月から選択
- 表示項目: 日付・かゆみスコア・かゆみ部位・水分量・食事・糖質・塩分・タンパク質・メモ
- ブラウザの印刷機能でPDF保存可能（`window.print()`）
- 印刷時はナビゲーション等を非表示にするCSSを適用

## データモデル

### day_records（日次記録）

- id: UUID（主キー）
- user_id: UUID（users テーブルの ID。NextAuth で管理）
- day: DATE
- itch_area: TEXT（かゆみの部位。カンマ区切りで複数保存。例: "頭,首,背中"）
- itch_score: INTEGER（かゆみスコア 0〜5。0 は未入力）
- water_ml: INTEGER（水分摂取量の合計。集計クエリ用）
- water_logs: JSONB（水分摂取ログ。例: [{"time":"08:00","ml":200}, ...]）
- exercise_text: TEXT（運動内容の自由記述）
- meals_text: TEXT（食事内容の自由記述）
- carbs_g: NUMERIC（糖質 g。手動入力。NULL は未入力）
- salt_g: NUMERIC（塩分 g。手動入力。NULL は未入力）
- protein_g: NUMERIC（タンパク質 g。手動入力。NULL は未入力）
- note: TEXT（メモ・症状・気づき）
- created_at / updated_at: TIMESTAMPTZ

### user_settings（ユーザー設定）

- user_id: UUID（主キー）
- water_target_ml: INTEGER（1日の目標水分量。デフォルト: 1500ml）
- carbs_target_g: NUMERIC（1日の糖質目標量。デフォルト: 130g）
- salt_target_g: NUMERIC（1日の塩分目標量。デフォルト: 10g）
- protein_target_g: NUMERIC（1日のタンパク質目標量。デフォルト: 60g）
- locale: TEXT（表示言語。"ja" | "en"）
- plan: INTEGER（加入プラン。0=free / 10=full。デフォルト: 0）
- updated_at: TIMESTAMPTZ

### users（OAuth認証テーブル）

- id: UUID（主キー）
- google_sub: TEXT（Google OAuth の sub。固有識別子）
- display_name: TEXT（表示名）
